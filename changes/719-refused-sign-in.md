Fixed

- **A sign-in the workspace doesn't accept offers signing in again, and never looks like a problem in the bundle** ([#719](https://github.com/uncoverthestack/databricks-bundle-inspector/issues/719)). When the Databricks CLI's saved sign-in for a target is turned down, such as one that was revoked or has expired, the CLI says `Invalid access token`. The graph showed that text in its note; it now shows the sign-in banner, as for an expired browser sign-in, and `databricks auth login --profile <name>` replaces the old sign-in with a new one. The command-line tool listed it as an error in the bundle and exited with `1`, or `0` with `--fail-on never`; it now exits with `3`, like the other sign-in problems, and prints the command to sign in again. Checked on Databricks CLI v0.299.0 and v1.28.0.
