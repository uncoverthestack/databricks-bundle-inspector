Added

- **A `{{name}}` SQL parameter used as a catalog, schema or table name is reported** ([#707](https://github.com/uncoverthestack/databricks-bundle-inspector/issues/707)). Databricks fills `{{name}}` in with the value in quotes, so `FROM {{catalog}}.sales.orders`, a name in backticks, or `USE SCHEMA {{schema}}` fails the run even when the parameter is passed. The new warning `sql_parameter_as_name` suggests `IDENTIFIER()`, which works. `USE CATALOG {{catalog}}` without backticks and `IDENTIFIER({{schema}})` run and are not reported. This includes ``USE CATALOG `{{catalog}}` ``, which `databricks bundle init default-sql` writes since CLI v1.13.0: the job deploys, then fails with `` Catalog ''<name>'' was not found ``. Checked with job runs on a serverless SQL warehouse, Databricks CLI v1.28.0.
