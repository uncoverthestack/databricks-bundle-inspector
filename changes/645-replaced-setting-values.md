Changed

- **Setting values Databricks replaces with its own now say what it will use** ([#645](https://github.com/uncoverthestack/databricks-bundle-inspector/issues/645)). A schedule's `pause_status`, a job's `performance_target` or a task's `run_if` written with a value outside the allowed list, including the wrong letter case such as `paused`, passes `bundle deploy`, and Databricks stores its own value: `UNPAUSED`, so the schedule runs; no performance target; or `ALL_SUCCESS`. The Databricks CLI's warning for these now says so and lists the allowed values. Other settings keep the CLI's text. Checked by deploying each value twice beside a correct job and reading the stored job back, on Databricks CLI v1.28.0.
