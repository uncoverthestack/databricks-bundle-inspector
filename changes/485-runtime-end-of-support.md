Added

- **Clusters on a Databricks Runtime near or past end of support** ([#485](https://github.com/uncoverthestack/databricks-bundle-inspector/issues/485)). A new check, `runtime_end_of_support`, reads each cluster's `spark_version`: all-purpose clusters, job clusters and a task's own cluster. A version whose support ends within a year gets a note with the date, such as *Databricks Runtime 15.4 LTS is supported until 2027-08-19*. One past end of support gets a warning that it may no longer get security fixes, and 10.4 LTS and earlier, which Databricks lists as end of life, a warning that runs may fail to start. `bundle validate` and `bundle deploy` don't look at the version. The dates come from the Databricks docs, read 2026-11-24, and a weekly check compares them with the docs pages so a new version or a moved date isn't missed.
