Fixed

- **A path written from the bundle root, in a file under `resources/`, is now reported as not found, as the Databricks CLI reports it** ([#518](https://github.com/uncoverthestack/databricks-bundle-inspector/issues/518)). The CLI reads a task, library or pipeline source path from the folder of the YAML file that writes it. The inspector also tried the bundle root, so `src/etl.py` in `resources/job.yml` showed no problem while `bundle validate` failed. For wheels and pipeline globs, which `bundle validate` doesn't check, the failure came only at deploy or when the pipeline ran. This often shows up after removing `git_source` from a job, as Git paths are read from the top of the repo. The finding now says `Did you mean "../src/etl.py"?`, adding the notebook extension when the path has none.
