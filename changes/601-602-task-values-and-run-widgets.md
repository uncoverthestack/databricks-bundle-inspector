Fixed

- **Task values of a for-each task are checked under the right name** ([#601](https://github.com/uncoverthestack/databricks-bundle-inspector/issues/601)). Values set inside a for-each loop are read by the inner task's key. The inspector had it the wrong way round: it warned on the inner task's key, which works, and said nothing for the loop's key, which fails the run with `No task values with key ... were found`. A read by the loop's key now gets the warning, with the inner task's key as the suggestion. A task that reads its own value that it never sets is now reported too, as it fails the same way. Checked by job runs on Databricks CLI v1.28.0.
- **A notebook run with `%run` keeps its widget warnings when it also reads a widget by a variable name** ([#602](https://github.com/uncoverthestack/databricks-bundle-inspector/issues/602)). `dbutils.widgets.get(name)` doesn't set a widget, so `dbutils.widgets.get("needed")` in the same notebook still fails the run when nothing sets `needed`. Checked by job runs on Databricks CLI v1.28.0.
