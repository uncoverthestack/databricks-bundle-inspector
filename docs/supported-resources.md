# Supported resources

The inspector reads the bundle resource groups below. How much it does with each one varies: jobs and pipelines get their own views and checks, a few others take part in specific checks, and the rest are read but have no view or checks of their own. The Databricks CLI validates the bundle configuration; the inspector adds the checks described in [Every check](checks.md).

For bundle syntax and configuration examples, see the official [Databricks bundle resource reference](https://docs.databricks.com/aws/en/dev-tools/bundles/resources) and [bundle configuration reference](https://docs.databricks.com/aws/en/dev-tools/bundles/settings). Each resource group in the table links to its Databricks reference. Those pages describe what Databricks can deploy; the second column describes what this inspector checks and displays. Databricks supports more resource types than the ones listed here.

| Resource group (Databricks reference) | What the inspector does |
| --- | --- |
| [`jobs`](https://docs.databricks.com/aws/en/dev-tools/bundles/resources#jobs) | Job and task graph, task details, dependency and duplicate-key checks, local file and library checks, and code checks for widgets, task values and secrets. |
| [`pipelines`](https://docs.databricks.com/aws/en/dev-tools/bundles/resources#pipelines) | Its own pipeline view, links to jobs that run the pipeline, local library and source checks, and secret references in supported source code and cluster settings. Pipelines without a job are included. Tables defined inside pipeline code are not shown. |
| [`secret_scopes`](https://docs.databricks.com/aws/en/dev-tools/bundles/resources#secret_scopes) | Matches secret references against bundle scope names and reports code that uses a resource key instead of its scope name. No view of its own. |
| [`clusters`](https://docs.databricks.com/aws/en/dev-tools/bundles/resources#clusters) | Links secret references in a cluster's settings to the tasks that use that cluster. No view of its own. |
| [`models`](https://docs.databricks.com/aws/en/dev-tools/bundles/resources#models), [`experiments`](https://docs.databricks.com/aws/en/dev-tools/bundles/resources#experiments), [`model_serving_endpoints`](https://docs.databricks.com/aws/en/dev-tools/bundles/resources#model_serving_endpoints), [`registered_models`](https://docs.databricks.com/aws/en/dev-tools/bundles/resources#registered_models), [`quality_monitors`](https://docs.databricks.com/aws/en/dev-tools/bundles/resources#quality_monitors), [`catalogs`](https://docs.databricks.com/aws/en/dev-tools/bundles/resources#catalogs), [`schemas`](https://docs.databricks.com/aws/en/dev-tools/bundles/resources#schemas), [`volumes`](https://docs.databricks.com/aws/en/dev-tools/bundles/resources#volumes), [`external_locations`](https://docs.databricks.com/aws/en/dev-tools/bundles/resources#external_locations), [`dashboards`](https://docs.databricks.com/aws/en/dev-tools/bundles/resources#dashboards), [`apps`](https://docs.databricks.com/aws/en/dev-tools/bundles/resources#apps), [`alerts`](https://docs.databricks.com/aws/en/dev-tools/bundles/resources#alerts), [`sql_warehouses`](https://docs.databricks.com/aws/en/dev-tools/bundles/resources#sql_warehouses), [`database_instances`](https://docs.databricks.com/aws/en/dev-tools/bundles/resources#database_instances), [`database_catalogs`](https://docs.databricks.com/aws/en/dev-tools/bundles/resources#database_catalogs), [`synced_database_tables`](https://docs.databricks.com/aws/en/dev-tools/bundles/resources#synced_database_table), [`postgres_projects`](https://docs.databricks.com/aws/en/dev-tools/bundles/resources#postgres_projects), [`postgres_branches`](https://docs.databricks.com/aws/en/dev-tools/bundles/resources#postgres_branches), [`postgres_endpoints`](https://docs.databricks.com/aws/en/dev-tools/bundles/resources#postgres_endpoints) | Read from the bundle, but no view or checks of their own. When a bundle has no jobs, the graph panel names the resource groups it contains. |

The graph's resource selector lists jobs and pipelines only.

Checks on source code read Python and SQL, including supported notebook formats. Scala and R code is not read. Bundle-wide checks, such as include patterns and unresolved variables, are documented in [Every check](checks.md).

The inspector tells the Databricks CLI not to run bundle Python or scripts, so resources defined only by bundle Python are not shown. See [How it works](usage.md#how-it-works) for what the CLI does when the inspector runs it, and [Setup and usage](usage.md) for the views.

The table follows the inspector's resource list, [`MODELLED_RESOURCE_GROUPS`](../src/bundle/graph/bundleGraph.ts). A unit test fails when the table and that list disagree, and a schema coverage test checks the list against the Databricks CLI schema.
